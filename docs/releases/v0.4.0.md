# mini-trellis v0.4.0 — 记忆体验（发布草稿）

状态：开发候选，尚未发布。最终发布条件和固定环境验收仍在核对。

本版围绕一次完整的知识循环：保存确认结论，新会话在开发中使用，纠正后维护同一主题，再次使用最新规则。

## 可靠记录

测试条目保留提供的实际结果，不再统一添加成功标记；日志不再固定声称开发完成，也不把没有关联提交解释成仅做规划。

同一 checkout 的记录、序号分配、journal/index 更新及已配置的提交步骤使用有界进程锁。记录器核对 index 的托管标记、表格和完整条目身份，再检查实际落盘结果。部分失败保留 journal；修复报出的结构后重试相同命令，可补齐索引而不重复记录。后续已有记录的计数不会因旧行修复而回退。

新的主题关联记录把内容版本纳入重试身份。修改同一主题后，即使用相同标题和摘要，也能记录新决定。旧 v1/v2 指纹继续可恢复；没有保存主题版本的旧记录无法据此辨别内容纠正，会明确提示这一限制。

默认仍写原 journal，旧日志与相对主题链接继续使用。不同 worktree 的未提交记录仍可能重号，Git union 不保证条目完整；发现重复序号会停止新增，等待审阅并修复 journal 和 index。独立 Markdown 记录仅为本地原型，不随本候选切换默认格式，也不自动迁移历史。

## 项目入口

检索、记录脚本和共享 SessionStart 使用最近的已初始化项目，并止于独立 Git 根。嵌套项目、linked worktree 与非 Git 项目按同一边界处理；不从父项目借用未初始化独立仓库的知识，不把诊断写入错误子目录或通过逃逸的 runtime 符号链接写出项目。

Hook 文件安装、运行、上下文送达和模型实际使用分别判断。已有宿主信任和权限继续由用户控制。

## 开始使用

从已有 README、docs 或知识主题中的一条真实规则开始。保存后沿返回的主题和日志链接回读；新会话直接提出相关开发需求，检查生成代码是否保留条件和否定。确认纠正后更新原主题，再次验证新会话。普通小改动和未确认想法无需新增记忆记录。

新安装默认不自动提交；已有项目明确配置保留。更新 CLI 后，先预览 `mini-trellis refresh --dry-run`，再刷新当前项目的脚本和技能。旧安装回退到不含记录锁的脚本后，应避免混用新旧写入器并发记录；topic v3 标记是 Markdown 注释，旧文档召回仍可读，旧写入器不理解其重试身份。

## English summary

This unreleased candidate preserves supplied test outcomes, verifies actual journal/index writes, serializes recording within one checkout, and keeps resumable partial failures. New topic-linked records include content versions in their retry identity. Recall, recording and the shared startup hook use the nearest initialized project within an independent Git boundary. Existing journals remain the default; separate worktrees and direct edits to one topic still require conflict review.

The usage guides show the first useful rule, a fresh development request, an in-place correction and reuse of the updated rule. Successful recording establishes saved notes, while implementation and validation retain their own evidence. Host permissions and trust are not changed automatically.
