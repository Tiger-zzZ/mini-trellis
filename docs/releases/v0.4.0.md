# mini-trellis v0.4.0 — 让确认过的知识持续用于开发

2026-11-16。

0.4.0 聚焦日常使用中的一条链路：记下确认的决定，下次开发沿用，决定变化时更新原文，代码完成后同步文档。

## 记录更连贯

确认或纠正项目约定后，Agent 按同一流程完成主题更新、一次内容核对和日志记录。现行规则维护一份正文，保留原来的条件、否定和语言；未来约定标明实现状态，开发时一并更新相关说明。日常小改动和讨论中的想法按需处理。

## 保存和重试更可靠

同一工作目录中的记录按顺序写入。记录器检查日志、索引及实际保存结果；如果日志已经写入而索引尚未完成，重试原命令会接着补齐。旧记录的修复保留后续记录的计数。

主题内容版本参与新记录的识别：修正同一份文档后，即使用相同的标题和摘要，也能留下这次更新的记录。已有 journal、主题链接和旧记录恢复继续可用。

测试记录保留提供的实际结果，开发状态由本次事实说明。

## 在当前项目中使用知识

检索、记录和共享启动入口统一定位到最近的已初始化项目，覆盖子目录、嵌套项目、Git worktree 和非 Git 项目。独立仓库各自使用自己的知识，运行记录也保存在对应项目中。

## 从一条真实规则开始

1. 在现有 README、docs 或知识主题中保存一条确认的规则。
2. 新开会话，直接提出相关开发需求，让 Agent 查找并使用规则。
3. 确认修改后更新同一主题，再次开发时沿用新约定。

## 升级

使用 0.3.8 的项目可在项目根目录运行：

```bash
mini-trellis upgrade --tag 0.4.0
mini-trellis doctor
```

使用 npm 直接安装或更新时，随后刷新项目：

```bash
npm install -g mini-trellis@0.4.0
mini-trellis refresh
mini-trellis doctor
```

每个项目分别刷新后，开启新的 Agent 会话。已有知识和显式配置继续保留。

## English summary

v0.4.0 connects confirmed decisions, topic updates, verification, and journal recording into one continuous workflow. The current rule stays in one document with its conditions and original language, and implementation changes update the affected descriptions.

Recording is serialized within a checkout, verifies journal and index contents, and resumes partial writes on retry. Topic content versions distinguish a correction from a repeated recording request. Supplied test results retain their meaning, and existing journals remain compatible.

Recall, recording, and the shared startup entry resolve the same initialized project across subdirectories, nested projects, worktrees, and non-Git projects. Upgrade from 0.3.8 with `mini-trellis upgrade --tag 0.4.0`, then open a new agent session. For direct npm updates, run `mini-trellis refresh` afterward. See the [upgrade guide](../upgrade.md).
