# mini-trellis v0.3.0 — Current notes, precise compact recovery

整篇被替换的笔记可以标明后继。查询当前问题时，现行笔记排在它所替换的历史笔记前面。Claude Code 和 Codex 在 compact 之后，可以按这一场会话找回压缩前的具体限制。

## 用户能感受到的变化

- **现行结论优先**：旧笔记写上 `status: superseded` 和 `superseded_by: <仓库相对路径>` 后，`mem recall` 把最后一篇现行笔记排在前面，并可附上它的短摘录。`--limit 1` 时也不会只留下旧笔记。`mem read` 给出同一条路径，不贴后继正文。
- **坏关系看得见**：目标缺失、越出文档来源、指向自己、成环，或链没有走到现行笔记时，会给出 `lineageFault`。更新的文件时间、只改一个章节、嵌套的元数据，都不会把整篇标成过时。
- **compact 后定位这一场**：Claude Code 与 Codex 的启动提示写上宿主送来的完整会话 id，并建议在当前项目执行 `mini-trellis mem context <id> --platform claude` 或 `--platform codex`。不加查询时，读取最近一次压缩边界之前的有限轮次；长回复不会把最后一条短限制挤掉。`--grep` 和相邻摘录都跳过压缩摘要。
- **三种失败分开**：没有会话 id 时不改绑另一场。历史还没落盘时，命令警告这场会话没有可读历史，然后以 `session not found` 退出。文件不可读时，警告写明读不了这场会话。这两条警告是 `session-history-missing` 和 `session-history-unreadable`。

## 兼容性边界

- OpenCode 和 Pi 还没有精确会话恢复。查笔记仍用 `mem recall` / `mem read`；要看本机历史时，用 `mem list --platform opencode` 或 `--platform pi`，再用完整 id 调 `mem context`。
- Claude 实际做过 resume 之后再 compact，完整会话 id 一致。是否发出独立的 `SessionStart:resume` 事件没有可靠记录，模板没有新增 resume matcher。
- Codex 的记录、更新与原生 compact 是同一项目里的分段验收。共享后台持有的旧 headless 会话没有被独立 TUI 直接接管。
- 本版没有新增 `mem recent`，也没有加入召回减负、路径提示或新宿主。

## 升级与核对

升级前请备份项目知识和自定义配置，包括被 Git 忽略的文件。

已有 mini-trellis 项目：

```sh
mini-trellis upgrade
mini-trellis refresh --dry-run
mini-trellis refresh
mini-trellis doctor
```

`upgrade` 更新全局 CLI。`refresh` 只更新受管理且未被本地修改的文件，保留 `.trellis/spec/`、`research/`、`workspace/` 和用户自己的配置。完成后开启新会话。Codex 仍需分别信任项目和 hook。

从 Trellis 迁入仍使用 `mini-trellis migrate --dry-run`，确认后再执行 `mini-trellis migrate`。
