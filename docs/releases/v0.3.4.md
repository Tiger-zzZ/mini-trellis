# mini-trellis v0.3.4 — Cursor 与项目现状维护

2026-11-04。

在 Cursor 中记录与找回项目知识，直接维护已有 README、docs 或 spec，让后续会话读到当前的项目说明。

## Cursor

在项目根目录初始化：

```sh
mini-trellis init -u your-name --cursor
```

使用 `mini-trellis-remember` 技能记录确认的结论，用 `mini-trellis mem recall` 找回相关知识，摘录缺少条件时再用 `mem read` 展开。

配置时保留用户已有的 command/prompt hooks、版本值和其他字段。无效的 JSON 或 hook 结构会保留并提示；`refresh` 遇到冲突停止，`doctor` 给出配置错误或缺失启动注册的详情。

Cursor 本地启动短入口已在 3.27.22 验证。hook 日志成功本身不证明模型收到或使用内容；短入口不可用时，仍可通过 `AGENTS.md`、项目技能与 `mem recall` 使用知识。Cursor 托管云端不运行 `sessionStart`，自托管机器未验证。不解析 Cursor 对话历史。

## 项目现状只维护一份

- 已有 README、docs 或 spec 就更新原文件，没有合适文件才新建短 spec；更新时保持原文件语言。
- 已实现能力核对代码或测试。已确认但尚未实现的约定与愿景单独写明，常量或配置值本身不证明行为已实现。
- 确认决定后更新同一篇说明，再用 journal 链接实际更新的文件。改名同步修正符号与路径引用；仅改名或排版不新增 journal。
- `add_session.py --topic` 支持根目录 `README*.md`、`docs/` 和 `doc/` 下的 Markdown，继续校验真实文件与项目范围。它校验路径并写入 journal，不代替模型更新正文。

迁移或增加宿主时，缺少 `.trellis/.gitignore` 会补上默认规则，已有用户规则保留。此操作不会取消 Git 对已跟踪文件的跟踪。

## 升级

先备份项目知识和自定义配置，包括被 Git 忽略的文件。已有 mini-trellis 项目执行：

```sh
npm install -g mini-trellis@0.3.4
mini-trellis refresh --dry-run
mini-trellis refresh
mini-trellis doctor
```

`refresh` 更新未被本地修改的受管文件，保留项目知识；遇到冲突按详情处理。已有安装需同时升级 CLI 并刷新项目脚本与技能，才能使用新的主题路径支持和维护规则。完成后新开会话。

从 Trellis 迁入仍先执行 `mini-trellis migrate --dry-run`，确认后执行 `mini-trellis migrate`，再为实际使用的宿主执行 `init`。详见[日常使用](../using_CN.md)和[迁移指南](../migration_CN.md)。
