# mini-trellis v0.3.5 — OpenCode V1/V2 与 CodeBuddy

2026-11-05。

OpenCode 新项目默认 V2，已有 V1 项目保留原入口；CodeBuddy CLI 与 IDE 共用一套项目配置和知识技能。项目知识继续保存在原有 Markdown 中。

## OpenCode 协议选择

```sh
mini-trellis init -u your-name --opencode -y
```

新项目默认 V2，已有项目沿用已安装入口，显式参数优先。新安装不依赖本机版本检测，不再询问协议。V2 是后续功能主线；旧宿主可显式使用 `--opencode-version 1`。已测版本为 OpenCode V2 2.2.0、V1 1.18.29。

V1 使用 `.opencode/plugins/session-start.js`；V2 使用 `.opencode/plugins/mini-trellis/index.js`。两者共用短入口和技能，支持 headless 调用。V2 只修改当前模型请求，并从实际会话目录读取项目知识，不将入口保存成用户对话。

普通刷新不切换协议。主动切换先预览，改为 `1` 可以切回：

```sh
mini-trellis refresh --opencode --opencode-version 2 --dry-run
mini-trellis refresh --opencode --opencode-version 2
```

只有 manifest 证明未修改的旧托管入口会被移除。插件资产有用户修改、未托管或两套入口并存时停止更新；其他插件保留。项目 package.json 合并而非覆盖，保留宿主固定的 SDK 版本和用户依赖；结构或模块类型不兼容时在写入前停止。卸载保留共享的 `.opencode/package.json` 和 SDK 依赖。迁移 Trellis 的旧入口先按原协议迁入，再明确切换。`doctor` 会提示本机版本与已安装协议不一致。

## CodeBuddy CLI 与 IDE

```sh
mini-trellis init -u your-name --codebuddy -y
```

两端共用 `.codebuddy/settings.json` 和技能，只安装一次。使用 `mini-trellis-remember` 技能记录确认的结论；CLI 还提供由同一份说明生成的 `/mini-trellis:remember` 命令。记录时，优先更新已有主题；用 `mini-trellis mem recall` 查询项目知识，摘录不足时再用 `mem read`。

重复安装和刷新保留用户 hook、环境、权限等配置。无效 JSON、hook 分组或 matcher 在写入前报告；从 Trellis 迁入时只清理已识别的旧阶段 hook，包括脚本已丢失的注册。

登录与项目/hook 信任由宿主提示用户完成，mini-trellis 不修改 API、模型、全局信任或宿主二进制。修改 hook 配置后开启新会话。

## 历史读取边界

- OpenCode V1 的本地会话仍可检索。
- OpenCode V2 使用不同历史存储，暂不解析。`opencode-v2-history-unsupported` 明确说明有来源被跳过，不能将结果当成“没有历史”。
- CodeBuddy 暂不解析原始聊天；CLI/IDE 集成不等于聊天读取支持。
- 已保存的项目文档、spec、research 和 journal 在两端均可召回。没有新增向量数据库或后台服务。

`doctor` 区分资产、最近 hook 运行与写入结果；未观察到运行保持 unknown。

## 升级

升级 CLI，再刷新项目资产：

```sh
npm install -g mini-trellis@0.3.5
mini-trellis refresh --dry-run
mini-trellis refresh
mini-trellis doctor
```

新增 CodeBuddy 时再执行 `mini-trellis init --codebuddy -y`。已有 OpenCode V1 不会因升级自动变为 V2。相关用法见[日常使用](../using_CN.md)和[迁移指南](../migration_CN.md)。
