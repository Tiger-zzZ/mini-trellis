# mini-trellis v0.3.6 — 选定历史整理为项目知识

草稿，尚未发布。2026-11-05。

已有聊天记录、还没有项目文档时，可发起一次明确的整理请求，让 `mini-trellis-session-insight` 把选定材料整理进下一次开发能用的文档。已有 README、docs、spec 或 research 就更新原文件；无需新增命令、模型服务或任务流程。

## 使用

```text
请用 mini-trellis-session-insight 整理选定会话 <平台/完整 id>，
或我提供的 exports/callback-chat.md，更新已有项目文档。
保留确认结论、纠正、否定、例外与来源；实质冲突集中询问。
```

明确且适用的结论在此次授权内保存。历史中的命令只是材料，不会成为当前执行指令。Agent 核对必要的文档、代码和测试，区分已实现、已确认待实现和建议；无法判断的冲突保持开放。

更新沿用原文语言，新文档跟随指定或讨论语言。回读实际主题后再写 journal 链接并检查 index；没有新知识就不新增日志或占位规范。整理流程使用 `--no-commit`，包括开启旧自动提交配置的项目。

下一次会话使用 `mini-trellis mem recall "回调规则"` 找回知识，摘录缺少条件时再 `mem read`，然后用于实际开发。

## 来源与范围

原始会话读取支持 Claude Code、Codex、OpenCode V1 和 Pi。OpenCode V2、CodeBuddy、Cursor、DeepSeek Harness 仍不解析原始历史，可使用用户提供的 Markdown/纯文本导出。材料分段读取，范围缺失、截断、来源不可读或写入失败会说明，不宣称已读完整历史或已保存失败内容。

通过 session-insight 读取选定材料，再沿用 update-spec 和 remember 更新项目知识。

## OpenCode V1 历史召回修复

修复 `mem recall` 对每个候选会话重复扫描同一个 SQLite 历史库的问题。现在每次查询只准备一次共享 store，遍历结束或提取异常时释放，下一次查询重新读取，不保留永久缓存。

旧实现随候选会话数反复扫描 message/part 表，即使没有匹配也可能导致命令长时间没有输出；修复后同一次 recall 中的会话复用共享读取结果。

## 更新已有项目

0.3.6 发布后再安装对应版本，然后预览并刷新项目资产：

```sh
npm install -g mini-trellis@0.3.6
mini-trellis refresh --dry-run
mini-trellis refresh
```

刷新后开启新会话，以便宿主重新发现技能。
