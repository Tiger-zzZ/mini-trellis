# mini-trellis · 产品路线图

**Less ceremony. More continuity.**

让每一次开发，都站在项目已经积累的知识之上。

mini-trellis 为 AI 编程提供轻量的项目记忆：把确认过的决定留下来，把相关证据找回来，让下一次会话自然接上进度。知识保存在项目里的 Markdown 中，随代码一起阅读、演进与复用。

更新：2026-10-12。v0.2 已发布；v0.2.1 贯通统一召回、知识记录与上下文恢复，核心开发与 Codex、Claude Code 验收完成。

## v0.2.1 · 项目知识，一处召回

项目规则、研究笔记、docs 和历史对话进入同一条检索链路。一个 `mem recall` 返回相关摘录、来源与定位；需要更多细节时，用 `mem read` 展开原文。文档自动发现，现有项目知识直接成为模型可用的上下文。

| 能力 | 用户获得的体验 |
| --- | --- |
| 统一召回 | 从项目文档与历史对话中找到相关依据，减少来回寻找 |
| 渐进阅读 | 先看短证据，再展开所需原文，让上下文围绕当前问题组织 |
| 自然沉淀 | 确认决定后更新已有主题，用 journal 留下过程与引用 |
| 会话连续性 | 启动与 compact 恢复时提供简短入口，延续项目知识 |
| 运行诊断 | doctor 展示最近 hook 执行与记录结果，定位实际运行状态 |
| 大目录发现 | 批量处理 Git 忽略检查，让文档发现适应更大的项目 |

  J --> K

## 下一步 · 更少打断，更高复用

### v0.2.x · 把体验磨细

围绕真实使用中的成本打磨细节，让模型用更少的动作获得足够的依据。

- **查询更直接**：改善中文与英文资料间的关键词匹配，减少重复改写和命中后的再次查询。
- **上下文更精简**：优化 resume 与 compact 相邻发生时的入口交付，让恢复上下文更紧凑。
- **记录更准确**：让简短概括保留确认范围，完成说明与实际文件更加一致。
- **安装更顺畅**：持续改善首次安装、已有项目升级与宿主诊断体验。

### v0.3 · 让记忆更贴近工作

在统一召回之上深化项目连续性，把“能找到”推进到“更容易用对”。

- **任务相关性**：结合当前文件、代码路径和问题主题，让最相关的依据更早出现。
- **知识沿革**：让当前规则、历史决定与替代关系更清晰，减少重新讨论和使用旧结论的成本。
- **连续工作体验**：打通跨会话接续与 compact 恢复，让项目上下文伴随工作自然演进。
- **效果评测**：用真实项目反馈和固定材料持续衡量召回质量、记录准确性、上下文与调用成本。

## 轻量，贯穿每一层

**项目里的 Markdown，是记忆的长期载体。** 人与模型共享同一份知识，直接阅读、直接编辑、随项目演进。

**按需提供上下文，是交互的默认节奏。** 短入口负责引导，相关证据支撑当前问题，完整内容在需要时展开。

**本地词法检索，是简单可维护的技术底座。** 文档自动发现，沿用现有宿主会话与文件结构。

**语言跟随知识本身。** 默认提示词英文，新笔记使用讨论或指定语言，更新沿用原文语言。

**四个宿主共享记忆体验。** Codex、Claude Code、OpenCode 与 Pi 使用一致的知识结构与记忆入口，真实体验优先围绕 Codex 和 Claude Code 打磨。
