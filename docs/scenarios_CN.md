# 使用场景

以下示例说明保存什么、如何在后续查找，以及怎样检查结果。示例规则需要替换成项目实际确认的约定。

## 从空仓库开始

完成[安装](install_CN.md)后，先保存一条约定。例如，确认 CLI 错误写入 stderr，JSON 结果写入 stdout。让 `mini-trellis-update-spec` 记录规则并添加索引链接。新开会话查询 `CLI stdout stderr`，在实现命令时使用它。

**检查结果：**来源写清规则，新命令按规则输出。

## 整理已有代码库

让 Agent 阅读已有 README、架构说明和相关代码，更新原文档中的用途、已实现能力、模块与约束。需要补充某个设计选择的原因时，用 [session-insight](history_CN.md) 整理选定的历史讨论。

**检查结果：**文档与当前代码一致，提议中的工作有明确标识。

## 留下故障修复经验

修复重复回调后，在回调规范中保存幂等规则，在调研里记录失败方案与原因，在日志中保留回归测试结果。后续会话修改重试逻辑前，先查询“回调 幂等”。

**检查结果：**返回的来源保留了修复成立所依赖的条件。

## 跨 Agent 和团队共享决定

安装团队使用的 Agent 集成，按仓库约定提交经过审阅的主题文档。使用另一种 Agent 的同事更新代码后，可以召回同一份 Markdown；原始私有对话继续保存在创建者的机器上。

**检查结果：**两个 Agent 找到相同的当前规则和来源路径。详见[配置与共享](configuration_CN.md)。

## compact 后继续工作

使用 Claude Code 或 Codex compact 交接给出的当前会话命令，再通过 `mem recall` 查找长期规则。其他平台可手动选择已支持的本地历史，或继续使用保存的主题文档。

**检查结果：**来源包含当前需要的条件。历史缺失或不完整时，先查看告警与已有文档，再继续修改。详见 [compact 恢复](recall_CN.md#compact)。
